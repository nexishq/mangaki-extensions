# Mangaki Extensions

Manga source extensions loaded at runtime by the Mangaki iOS app.

## Install in the app

More → Extensions → Add repository, then paste:

```
https://nexishq.github.io/mangaki-extensions/
```

## Layout

```
src/
  source.ts       — shared Source interface + DTO types
  host.d.ts       — typings for the native `host` bridge
sources/
  <id>/
    source.ts     — implementation
    manifest.json — metadata (id, name, version, lang, icon path…)
    icon.png      — optional 64×64 icon
build.mjs         — esbuild driver, emits dist/
versioning.json   — top-level index, auto-generated by `npm run build`
```

## Development

```bash
npm install
npm run build
```

`dist/` ends up looking like:

```
dist/
  versioning.json
  sources/<id>/source.js
  sources/<id>/manifest.json
```

Host the contents of `dist/` on GitHub Pages, an S3 bucket, or any HTTPS
static host. The repo root is not enough: it only has the `.ts` sources,
the built `source.js` bundles exist in `dist/` alone. The iOS app's
"Add repository" screen fetches `<base-url>/versioning.json` and
downloads bundles relative to that.

### Deploying

This repo serves `dist/` from the `gh-pages` branch:

```bash
npm run build
cd dist && touch .nojekyll && git init -q -b gh-pages && git add -A \
  && git commit -qm "Deploy" && git push -f <repo-url> gh-pages
```

Automatic deploys need a GitHub Actions workflow (build, then
`actions/deploy-pages` with `path: dist`); add one once a token with the
`workflow` scope is available.

### Smoke test

```bash
swift test_runtime.swift dist/sources/mangadex/source.js
```

Loads a bundle in JavaScriptCore and runs list → details → chapters
against the live site.

## The Source interface

Every `sources/<id>/source.ts` default-exports a class implementing
`Source` from `src/source.ts`:

```ts
import type { Source, ... } from "../../src/source";

export default class MySource implements Source {
  async mangaList(filter, cursor) { ... }
  async mangaDetails(slug)        { ... }
  async chapters(mangaID)         { ... }
  async pages(chapterID)          { ... }
}
```

All HTTP goes through `host.fetch(url, init)` (see `src/host.d.ts`) —
DO NOT call `fetch` directly, the JS engine isn't a browser context.

## Native host API

Available globals inside an extension:

- `host.fetch(url, init?)` → `Promise<{ status, body, headers }>`
- `host.solveDDoSGuard(domain)` → `Promise<{ cookies }>`
- `host.log(message)` — pipes to iOS unified logging

## Adding a new source

1. `mkdir sources/myservice && cd sources/myservice`
2. Create `manifest.json`:
   ```json
   {
     "id": "myservice",
     "name": "MyService",
     "version": "0.1.0",
     "language": "en",
     "nsfw": false,
     "bundle": "sources/myservice/source.js",
     "icon": "sources/myservice/icon.png",
     "baseURL": "https://example.com",
     "description": "..."
   }
   ```
3. Create `source.ts` implementing the `Source` interface.
4. `npm run build` — regenerates `versioning.json` automatically.
5. Commit, push and deploy. Users update via "Add repository" in the app.
